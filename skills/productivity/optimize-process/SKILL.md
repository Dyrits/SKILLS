# Optimize process

Analyze an existing recurring process and recommend a simpler one. Treat a person and an agent as possible performers of each step, including the agent running this analysis.

## Map the current process

Trace one real cycle from trigger to finished result. Record the steps, decisions, handoffs, approvals, rework loops, and who performs each part. Separate active effort from elapsed time spent waiting. Use existing examples or artifacts where available; ask for the few missing facts that would change the recommendation. Mark uncertain parts as assumptions.

## Find friction

Look for waiting, repeated work, avoidable handoffs, unnecessary processing, and manual work an agent or tool could perform. Identify why each step exists before removing it, especially when it provides a required decision, review, or control. Prefer changes that remove a cause of delay over changes that merely make one step faster.

## Design the future process

Show the revised sequence and who performs each step. Remove steps that add no value, automate suitable work, reduce handoffs, and run independent steps in parallel when useful. Put human decisions and review where they affect the outcome. For each recommendation, state what must change, who owns it, and how to try it on the next cycle.

## Describe impact

Compare the current and proposed process in terms of elapsed time, human attention, agent runtime, rework, and quality where those effects matter. Count agent-performed work at its likely runtime plus human setup and review, rather than translating it into human-only days or weeks. Keep one-time setup separate from recurring effort and distinguish time saved per cycle from shorter end-to-end lead time.

Use observed timings if available. Otherwise give a rough range in hours or minutes only when its assumptions are clear; use a directional statement when numbers would be guesswork. Do not invent error rates, cost savings, employee satisfaction scores, or percentage improvements. Say which assumption has the greatest effect on the estimate and what to observe during a small trial.

## Output

Give a compact before/after process comparison, the highest-value recommendations in priority order, a practical implementation sequence, and the expected impact with its evidence or assumptions. Make the first trial concrete enough to run. If the current process is already sound, say so and describe any remaining friction without manufacturing a change.
