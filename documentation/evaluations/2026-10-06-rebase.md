Written 2026-10-06 (UTC). Runs took place on 2026-10-06.

## Result

The eight behavior evals (2 to 9) were run. Six met every expectation on the first pass or after a prompt fix; the skill text needed no change. The misses were eval defects: three prompts (2, 3, 8) ran into the fixture's incompatible `TIMEOUT_SECONDS` conflict (45 versus 60) with no user answer, so the runner correctly stopped before the later expectations; eval 6's prompt gave no answer to the skill's question; eval 9 over-specified a path the skill closes. Each prompt now carries the answer it anticipates, and the affected evals were re-run. Eval 4 shows no evidence for one expectation (the check that the local branch still equals its validated tip). The trigger and no-trigger evals (1, 10, 11) were not run.

## Method

Simulated runs with real Git in scratch repositories that have a local bare remote. Runners read the skills by path and could not dispatch subagents, so they handled branches in sequence. Where a skill step asks the user, the runner stopped and wrote the question as its final message, unless the prompt held the answer.

## Failures and limits

- The first runs of evals 2, 3 and 8 stopped at the conflict question, which is what the skill requires. The prompts did not supply a decision, so the later expectations were unreachable. They now state the decision (keep develop's 45 seconds).
- In evals 2, 3 and 8 the resolution makes the only `fix/a` commit empty, so Git drops it and `fix/a` equals the target. The runners reported that and warned that pushing it removes the commit from the remote. The fixture therefore never shows a surviving conflicting commit.
- Eval 4: the transcript shows the lease form, the readback, the worktree removal and the offer to delete backup refs, but no step comparing the local tip to the validated tip.
- Eval 6: the runner also asked to confirm origin as the destination, because no upstream is configured. That is consistent with the skill.
- Eval 9: the skill requires marking a branch `unknown` and asking when a subagent's liveness cannot be established, so the report step is unreachable in that case. The expectations now ask for a stop message that accounts for every branch.
- One run per eval, same session as grader, no baseline.

## Not run

Evals 1, 10 and 11 (trigger and no-trigger); a live trigger firing; a real subagent dispatch; a push to a network remote.
