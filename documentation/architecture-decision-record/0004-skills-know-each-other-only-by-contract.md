# Skills know each other only by contract

Status: superseded by [0005: Make skills autonomous](./0005-make-skills-autonomous.md). The original rationale below is retained as history.

Each skill is complete for its own job, calls others for theirs, and knows them only by contract: a skill may name another skill and the outcome it expects from it, never that skill's rules, formats, or paths. The test is whether a skill's internals can be rewritten without editing any other skill.

Knowledge of another skill's internals had leaked across the collection. Root paths such as `CHANGELOG.md`, `GLOSSARY.md`, and `CONVENTIONS.md` were named in dozens of skill files, `document` was about to carry a table of files `model-domain` owned, and `memorize`'s `AGENTS.md` pointer was copied word for word into `setup-ai-workspace`. Each copy drifted silently and turned a one-skill change into a sweep. This supersedes the looser answer of the 2026-10-06 skills audit ("default to autonomous").

## Decisions

- **`document` owns every shared project document**: where it lives and what shape it takes. That covers requirements, specifications, drafts, backlog, working state, tasks, the changelog, the glossary, code conventions, and architecture decision records, with their format files. A path belongs to `document` when more than one skill reads or writes it; an artifact one skill alone reads and writes (handoffs, research reports, teaching workspaces) stays with that skill.
- **Thinking skills settle content and call `document` to write it.** `interview` settles decisions in rounds of questions (it was `refine`). `delineate` settles what terms mean against the glossary, the code, and concrete scenarios (it was `model-domain`, narrowed to words). `codify` drafts and confirms code conventions (new, taken out of `model-domain`, since conventions hold no domain terms). The two last use `interview` for their questions. `document` calls none of them.
- **Shared documents live under `documentation/`**: `documentation/changelog.md`, `documentation/glossary.md`, `documentation/conventions.md`. A multi-context repository gives each context its own `documentation/` folder beside its code, listed in `documentation/glossary-map.md`. `AGENTS.md`, `README.md`, and other platform files stay where their tools look for them.
- **Other skills name documents by role** ("the changelog", "the glossary", "working state") and call `document` to resolve the path.
- **Each skill owns its own `AGENTS.md` pointer** and adds it itself. A setup skill calls the skill to add its pointer instead of carrying a copy of the text.

## Considered options

- **Fully autonomous skills**: each skill restates what it needs. No dependencies, but every shared protocol (the changelog format, the interview discipline) is copied and drifts.
- **`model-domain` owns the glossary, conventions, and decision record formats**: the previous split. It fused three unrelated jobs into one skill (conventions are project-agnostic, tied to no domain) and forced `document` to know another skill's files.
- **Retiring `model-domain` into `interview`**: a term is a decision about a word, so `interview` could settle it. Rejected because terms and conventions each have their own trigger and callers, and the checks against the glossary and the code are not something a general interview does.
- **A full documentation map in each project's `AGENTS.md`**: every skill could look up paths without a call, but the map costs context on every turn and every project's copy goes stale when the layout changes. A one-line pointer to `document` gives the same protection.

## Consequences

`check-skills.py` cannot verify contracts; the test above is applied in review. The changelog no longer collides with a release `CHANGELOG.md` generated by tools such as changesets or release-please. No migration is provided: a project with root files keeps them until someone moves them.
