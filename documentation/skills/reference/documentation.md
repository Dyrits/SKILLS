## What it does

`/documentation` helps write and maintain technical documentation for a specific reader and task. It gives useful content prompts for README files, API references, runbooks, architecture documents, and onboarding guides. Those prompts do not override an existing repository format.

## When to reach for it

Type `/documentation`, or the agent reaches for it automatically when you ask it to write or update technical documentation. For documents that instruct agents, [writing for agents](writing-for-agents.md) also applies.

## Match the reader's task

A runbook needs a procedure and recovery steps that someone can follow during an incident. An API reference needs accurate requests, responses, and error behavior. A README needs a path to a first successful use. Start with the reader's task, then include the parts that support it.

## Common questions

**Does it replace this repository's documentation template?**
No. Repository-specific formats take precedence. The document-type lists are prompts for useful content.

**Does it also write specifications or research notes?**
Use [to-specifications](../workflow/to-specifications.md) for a feature specification and [research](../shaping/research.md) for a cited investigation. This skill covers technical documentation intended to explain a system or procedure.

## It's working if

- A reader can complete the task the document addresses without guessing a missing step.
- Examples and commands match the current system.
- Links point to maintained sources instead of repeated text.

## Where it fits

This is a standalone reference for technical writing. [Writing for agents](writing-for-agents.md) adds guidance when agents consume the document. [What is next](../getting-started/what-is-next.md) maps the full skill set.
